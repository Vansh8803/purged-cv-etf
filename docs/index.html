Does leakage-safe cross-validation change what a backtest reports?

01The question, and what one row is

Financial labels are not points in time, they are windows. A label that takes ten days to resolve overlaps the next nine rows, so two nearby rows partly share an outcome. Cross-validation assumes rows are independent, and when they are not, training rows can carry answers to test rows.

The standard fix is purging: drop any training row whose label window overlaps the test fold. We wanted to know whether it changes the reported number, and by how much.

One row is one trading day for one ETF. It carries that day's open, high, low, close, adjusted close and volume; ten features computed from earlier days; a binary label; and t1, the date that label resolved. That last column is what purging is defined in terms of.

What we found

Almost nothing — and the reason turned out to be better than the result we expected. How much a careless backtest flatters itself depends on how you cut the folds, not on whether you purge. We cut ours as blocks of time, which leaks 0.33% of training rows, so purging had almost nothing left to remove.

Shuffle the same folds and the leak jumps to 88%. You can try that in section 3.

02The label

For each day we draw two price levels around the close and ask which one the price touches first over the next ten trading days. Reach the upper level first and we label the day 1; hit the lower one first, or drift without reaching either, and it is 0.

We set the gap from recent volatility rather than using a fixed percentage, because a 2% move means something very different in a calm month than in a crash. Drag through the slider and watch the barriers widen as 2008 arrives.

A mistake we caught

Our first barriers were 2.5 times narrower. At that width a single day's trading range was usually already wider than the gap, so the median day resolved in one bar and the ten-day limit almost never mattered.

That would have wrecked the project. One-bar windows barely overlap, so there would have been nothing for purging to remove, and we would have reported our own parameter choice as a finding. Widening cost us sample size — 1,575 effective observations down to 662 — and we took that trade because the overlap is the thing we are studying.

03Why ordinary cross-validation breaks here

If today takes six days to resolve and tomorrow also takes six, the two windows share five days of price history. Put today in training and tomorrow in testing and we have trained on a row whose answer was decided by almost the same future prices as the row we are about to be tested on. The score comes out too high and nothing looks broken.

Our 4,302 rows per ETF carry about 662 independent observations once that overlap is accounted for. Every error bar on this page follows from that number.

Alongside purging we apply an embargo, dropping rows that start in the few days just after a fold. Our features use 20-day rolling windows, so a row just after a fold computes its features partly from bars inside it.

How much leaks depends on how you cut the folds

We chose blocks for the control. Our specification says "standard 5-fold K-fold", and sklearn.KFold does not shuffle by default. It is also the harder test for our own claim, since shuffling would have handed us a huge gap against a control nobody sensible would use.

04The data

Five ETFs — SPY, QQQ, IWM, TLT and GLD — rather than individual stocks, because a list of stocks silently excludes everything that went bankrupt. GLD launched in late 2004, so our range starts in 2005. Daily bars from Yahoo Finance via yfinance, downloaded once in October 2026 and cached, because Yahoo revises adjusted prices after the fact and a fresh download would quietly change numbers we had already computed.

Key variables. Open, high, low, close, adjusted close and volume. The high and low are load-bearing: our label asks whether a price level was touched during the day, not where the day closed.

Table 1. 5,282 raw daily bars per fund, no missing values, all five on the same NYSE calendar. Rows drop after the 200-day warm-up our longest moving average needs.

The quality problem that mattered. Dividend-paying funds have an adjusted close that differs from the raw close, and our label depends on intraday highs and lows. Mixing raw intraday prices with a volatility threshold built from adjusted returns would let a scheduled dividend drop trigger a false stop-loss, so we scale the highs and lows by the same factor. GLD pays no dividend, so its factor is exactly 1.0 on every row, which gave us a free test of that code path.

05Preprocessing, and the leak that is easy to miss

Ten features, all computed from information available on or before a day and then shifted one bar, so a row dated t holds values computed up to t−1.

Trailing returns
log return over 1, 5, 10 and 20 days
Realised volatility
standard deviation of daily log returns, 20-day window
Volatility of volatility
standard deviation of that 20-day series, 20-day window
Distance from average
(close − MA) / MA for 20, 50 and 200 days
Volume z-score
volume against its own 20-day mean and standard deviation

Computing these over the whole dataset is not a leak. Every one is a deterministic rolling function of its own past, so a row's value does not change depending on which fold the row lands in. Nothing is estimated from the sample.

Preparing them over the whole dataset is a leak. A scaler learns each column's mean and standard deviation. Fit it once on everything and every fold's test rows have contributed to the numbers used to transform them. The model never saw those rows, but information from them arrived through the back door. So our scaler and imputer are fitted inside each fold, on training rows only. A test spikes a test-fold value to 109 and asserts the fitted scale does not move.

What the model may not see

The raw bars at t are withheld, obviously. Less obviously, so is sigma — the volatility that sets the barrier width. Handing it over would tell the model how far price must travel for the label to fire. The shifted version, realized_vol_20d, is the honest one. That exclusion turned out to matter far more than we expected; see the floor in section 7.

06The baseline and the models

All five predict the same binary target, so precision and AUC mean the same thing in every row of the comparison. Two of them are not fitted at all and are scored through exactly the same code path as the learned ones — same folds, same test rows, same metric, same purging. That is the only way the comparison is like for like.

Buy and hold
The reference. Acts every single day. Not really a model: the thing every strategy has to beat, and the number precision is read against. Its AUC is exactly 0.500, because it scores every day the same and so cannot rank.
MA crossover
The baseline. Long while the 20-day average price sits above the 50-day, applied one bar late. No learned parameters, so it cannot leak or overfit — which makes it a fixed reference point across every scheme.
Logistic regression
The floor. Assumes the log-odds of the label are a straight-line combination of the ten features and fits eleven numbers. If nothing beats this, complexity has not earned its place.
Gradient-boosted trees
Fits a shallow tree, looks at what it got wrong, fits another targeting those errors, 200 times over. Captures interactions a linear model cannot. Capacity held down hard, because ~660 effective observations is the binding constraint rather than model class.
Meta-labelling
Two stages. The crossover rule decides when to consider acting; a model trained only on the days that rule fires decides whether to take the signal. It can filter, never generate.

No neural network, and no hyperparameter search. Settings are fixed and chosen for the sample size rather than tuned on it, which keeps our honest trial count at five — the number the Deflated Sharpe Ratio in section 11 depends on.

07How we scored them

Three schemes, all built on one shared overlap rule so they cannot drift apart. Purged 5-fold with an embargo is our real number. Standard 5-fold is the control, run deliberately and wrong for this data, so the effect of purging can be measured at all. Walk-forward, expanding only ever trains on the past. We also held back 2023–2025 entirely and opened it once, at the end.

We report precision against the rate you would get by acting every day, coverage beside it because precision alone rewards abstention, AUC for ranking, and Sharpe with its standard error. One baseline needs saying out loud.

Read this before the results

An AUC of 0.544 means no signal, not a weak one. We generated fake price series with no predictability at all, ran the whole pipeline on them, and the full feature set still scored 0.544.

The cause is our own label. High volatility means wide barriers, wide barriers are less likely to be touched, an untouched barrier times out, and a timeout counts as 0. So trailing volatility predicts the label without any skill at predicting direction. Among days that did touch a barrier, 50.9% went up — a coin flip, exactly as it should be.

Without that check we would have reported an AUC of 0.55 as a modest edge when it is the floor. Every AUC below is read against 0.544.

The same synthetic machinery told us how small a signal we could have detected: we start to pick up predictability at an autocorrelation of about 0.4. The real figure in these funds runs from −0.107 to −0.010, an order of magnitude smaller and the wrong sign. So when we find nothing, we can say we found no edge above roughly 0.4 rather than just shrugging.

08Results

Table 2. AUC by model and scheme, averaged over the five funds. Logistic regression is the only model clearly above the 0.544 floor. Both handwritten rules sit below it, which means a model knowing nothing but trailing volatility would beat our baseline.

The gap we went looking for — control minus purged — is effectively zero. Swept across every embargo from 0 to 20 bars, the largest value anywhere is about one thousandth of an AUC point, against a single fold's standard error of seventeen thousandths. Its direction even changes from fund to fund, so we cannot tell you its sign.

Table 3. Control minus purged, in AUC × 1000. The two handwritten rules come out at exactly zero, as they must, since a rule is not fitted and cannot care which rows we withheld.

The best classifier turned out to be the worst strategy

Logistic ranks days better than anything else and makes the least money. Those are different questions: AUC asks whether the ordering is right, Sharpe asks whether the days it chose to hold went up by more than the trading cost.

Table 4. Pre-holdout, out of fold, no trading costs. matched is the Sharpe from holding the same number of days chosen at random, which separates how well a model chose from how often it was invested.

Most of the fall is not skill. Logistic is invested 22% of the time, and sitting in cash forfeits the market's drift whatever you pick — Sharpe scales roughly with the square root of exposure, so its ceiling was already 0.22 against buy-and-hold's 0.48. Then it picked slightly worse-than-random days, and costs took the rest.

09Error analysis

An error is a day a model said act and the lower barrier fell first, out of fold, so every one is a day it had genuinely not been trained on. Acting every day is wrong 59.5% of the time; meta-labelling is wrong 51.3%, logistic 53.2%, the trees 55.5%.

Errors concentrate where the barriers are widest. The error rate climbs from about 0.48 in the calmest fifth of days to 0.64 in the most volatile fifth, and 2008 is the worst year for every model. The costliest individual mistakes are almost all October 2008, January 2009 and March 2020, mostly IWM, at ordinary confidence between 0.52 and 0.70 — the models were not unusually sure, just ordinarily sure and badly wrong.

It is the same mechanism as the 0.544 floor. The conditions they fail in are the conditions their edge is built on, which is worth saying plainly rather than burying: these models are least reliable exactly when it would matter most.

10Strategy lab

This changes how the model is evaluated, not what the strategy does. All three schemes score the same model on the same days; only the training rows differ. We precomputed the position series and the browser does cost and execution arithmetic on top, which is how 1,764 slider combinations fit in half a megabyte.

Worth trying: switch between purged and the control and watch the curve barely move. Then drag the cost slider with the trees selected, and again with buy-and-hold, to see turnover do its damage. Hover the chart to inspect any day.

11The holdout, opened once

We fixed 2023–2025 in config.yaml before any modelling and did not look at it until everything above was finished. Then we fitted each model once, predicted those years, and wrote the numbers into our decision log before discussing them.

Table 5. Holdout results, averaged over the five funds, no costs. Precision is read against the positive rate of 0.437.
The purged estimate held

Logistic scored 0.5755 under purged cross-validation before the holdout and 0.5754 on it. Every model held within 0.024 on three years nobody had looked at.

That is the strongest thing on this page. Whatever our pipeline was measuring, it measured it stably, which is exactly what we built it to establish.

Buy-and-hold still won, its Sharpe rising from 0.480 to 1.116. That is the market and not skill — SPY returned 88% over those years and QQQ 138%. Every strategy roughly doubled for the same reason and none beat the index. Nothing reaches a t-statistic of 2, because 744 days gives a Sharpe standard error of 0.580 rather than 0.242.

Against us

Our one significant finding reversed. Before the holdout, logistic's selection edge was −0.164 with a t of −2.36, the only result we had that cleared two standard errors. We wrote that it was measurably picking bad days. On the holdout the same model's edge is +0.179.

Something that flips sign out of sample was noise, so that significance was a false positive — the exact failure this project is about. We found it in our own strongest claim, which is why we are telling you rather than dropping it.

The trees' holdout edge of +0.292 with a t of 3.4 is the best-looking number in that table and we are not claiming it. It is one figure among roughly sixty, from five funds, and it quadrupled from +0.071 before the holdout, which is what noise does. Its Deflated Sharpe Ratio is 0.860, short of any bar we would accept. That ratio asks whether our best model beat what the luckiest of five skill-less attempts would have scored, and the answer is not clearly yes.

12What we would not claim

  • Our 4,302 rows per fund carry about 662 independent observations. Most differences we could report are smaller than their own uncertainty, which is a property of daily data rather than something better code would fix.
  • Barrier width is our most consequential single choice, and we fixed it before scoring anything. Afterwards we measured what it cost. Narrower would have been worse, not better: at ±1σ the model scores 0.505 against a floor of 0.502, which is nothing at all. Wider would have scored slightly higher at the price of more effective sample. We could not act on any of this even if we wanted to, because the holdout was already open.
    Table 6. Barrier width against what the model can actually find. The floor moves with the width, because wide barriers time out and trailing volatility predicts timeouts, so only the lift is comparable across rows.
  • Our label merges "went down" with "went nowhere", and only the second is predictable from volatility. That is where the 0.544 floor comes from.
  • The five funds share calendar dates, so rows overlap across funds as well as across time. We fitted one model per fund to keep purging one-dimensional, which sidesteps the problem rather than solving it.
  • Four of five folds train partly on the future, so the cross-validated equity curves measure generalisation rather than simulating trading. Walk-forward does not do this, and it agrees.
  • Our Sharpe standard error assumes independent returns. Daily returns are serially correlated and volatility clusters, so 0.242 understates it.
  • No embargo we could afford covers a 200-day moving average, so a little feature overlap survives at every fold edge.
  • The holdout is 744 days. It confirmed that our AUC estimate held, but it cannot resolve any difference between strategies.

13Reproduce it

Everything on this page comes out of the repository, from cached data that ships with it. No credentials and no downloads. The two model scripts dominate the runtime.

# setup
python -m venv .venv
python -m pip install -r requirements.lock.txt

# rebuild everything this page shows
python src/data_process.py
python scripts/build_labels.py
python scripts/run_models.py
python scripts/run_backtest.py
python scripts/open_holdout.py
python scripts/build_site_data.py
python scripts/build_site_findings.py

# check it
python -m pytest -q                   # 161 tests
python scripts/check_site_data.py     # site vs Python agree

The splits are code, not prose: PurgedKFold, WalkForward and NaiveKFold in src/cv.py, all built on the one overlap rule in src/purging.py. The test suite asserts the properties rather than the outputs — that no surviving training row's window overlaps its test fold, and that the embargo is exclusive at the start and inclusive at the end.

Every decision behind this is dated and reasoned in decision-log.md, including the ones we reversed. Setup, reproduction steps, data access, citations and our AI-use disclosure are in the README.
